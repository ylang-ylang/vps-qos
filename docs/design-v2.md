# VPS QoS 带宽估计器 — 设计文档

## 目标

在已知 VPS 标称上限的前提下，判断当前是否拥堵：
- 不拥堵 → 输出标称上限（让流量跑满）
- 拥堵 → 输出当前实测速度上限（窗口化最大值，主动限速保护高优先级服务）

## 核心架构

### 两层估计器

1. **窗口化最大值滤波器**（已实现）：跟踪"链路最多能跑多快"（单边截断观测，卡尔曼做不了）
   - 只记住窗口内见过的最大观测速率
   - O(1) 时间 O(1) 空间，3 个子窗口槽位
   - 冷启动天然解决（第一个低值样本不会锁死后续学习）

2. **卡尔曼滤波器**（本轮新增）：融合多个因子的"拥堵概率"，回答"现在是不是拥堵了"
   - 每个因子独立、等价处理：输出 `(triggered: bool, value: f64)`（触发了吗？触发时当前网速多少？）
   - 卡尔曼用似然乘法融合多个因子的独立概率估计
   - 每个因子的可信度（测量噪声 R）可以动态调整（因子时好时坏时自动降权）

### 最终输出逻辑

```
如果 卡尔曼融合后的拥堵概率 > 阈值（可配置）
    → 拥堵，输出 窗口化最大值（当前实测速度上限）
否则
    → 不拥堵，输出 标称上限（配置项，VPS 购买时就知道的固定值）
```

## 因子设计原则（硬性约束）

- **所有因子一视同仁**：没有优先级、权重、搭配判断，一个因子触发了就是触发了，触发时当前网速是多少就是多少
- **因子只回答两件事**：触发了吗（bool）？触发时当前网速多少（f64）？不做任何其他判断
- **卡尔曼负责融合**：多个因子的独立概率估计用似然乘法融合，不需要人工写"该信谁"的规则

## 卡尔曼测量模型

状态：`[拥堵程度]`（标量，0=完全不堵，1=完全堵死）

观测：每个因子触发时提供一个观测值 `y_i = 网速值`，似然函数是 `p(y_i | 拥堵程度)`，多个因子的似然相乘得到联合似然。

具体实现：
- 因子触发时：`y_i = value`，测量噪声 `R_i` 根据该因子的历史表现动态调整（残差反馈）
- 因子不触发时：不产生观测（不是"观测到0"，是"这次没有观测"）
- 多个因子同时触发：顺序更新（同一时间戳，dt=0 的连续更新），卡尔曼数学自动处理多源融合

## 配置项（全部走外部 JSON，不允许硬编码）

- `nominal_ceiling_bps`：标称上限（VPS 购买时就知道的固定值，比如 200 Mbps）
- `congestion_threshold`：拥堵判定阈值（卡尔曼融合后的拥堵概率超过这个值就算拥堵，比如 0.7）
- `window_seconds`：窗口化最大值的窗口长度（已实现，60 秒）
- `sample_interval_seconds`：采样间隔（已实现，2 秒）
- 卡尔曼的 Q/R 矩阵初始值、可信度调整的学习率等（参考旧实现的做法，但这次要更简单）

## 测试要求

1. **用一个显然不合理的因子测试卡尔曼的融合能力**：比如"如果当前分钟数是偶数就触发"（跟真实拥堵完全无关），验证卡尔曼能正确识别这个因子的观测跟真实状态不一致，自动降低它的权重（R 变大），测试完后删除这个测试因子
2. 多个因子同时触发时的融合行为（顺序更新，dt=0）
3. 因子时好时坏时的自适应（R 动态调整）
4. 现有测试全部仍然通过

## 已知限制

- 窗口化最大值依赖"链路有流量在打"，如果完全空闲就测不出来（这是 BBR 的已知限制，需要 ProbeBW 主动探测，但对我们这个场景，HAProxy 本身就有流量在打，所以不是阻塞问题）
- 卡尔曼融合多个因子的概率估计，需要每个因子的观测模型是合理的（如果某个因子的观测跟真实拥堵完全无关，卡尔曼会通过 R 动态调整降低它的权重，但需要足够多的样本才能学会）
